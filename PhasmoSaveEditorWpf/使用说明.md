# 恐鬼症存档修改器（WPF 版）使用说明

改恐鬼症（Phasmophobia）本地存档的工具。这是重做的桌面版，相比只能改金钱和等级的旧 Python 版，现在能改**存档里的全部 597 个字段**，并对颜色、字典、列表、外观等复杂类型做了专用编辑器。

---

## 一、运行

- **免安装版**：双击 `dist\PhasmoSaveEditor.exe` 即可，无需安装 .NET。
- **开发运行**：`dotnet run --project PhasmoSaveEditorWpf\PhasmoSaveEditorWpf.csproj`

界面打开后会自动定位并读取默认存档。找不到时可点「浏览…」手动选择。

## 二、改之前必读

1. **必须完全退出游戏再改。** 游戏运行时改动无效——退出游戏那一刻，它会把内存里的旧存档写回磁盘，正好覆盖你的修改。程序检测到 `Phasmophobia.exe` 在运行时会**拒绝写入**。

2. **存档位置**（不在 Steam 游戏根目录，在 AppData\LocalLow 底下，这是 Unity 的规矩）：
   ```
   %USERPROFILE%\AppData\LocalLow\Kinetic Games\Phasmophobia\SaveFile.txt
   ```

3. **云存档可能回滚。** 本作接入了 Unity CloudSave，Steam 云同步默认也开着。如果进游戏发现进度被打回原形，就是云端盖掉了本地——需要在 Steam 里右键游戏 → 属性 → 通用，临时关闭云同步后重试。

4. **每次写入前自动备份**，文件名形如 `SaveFile.txt.bak-20261022-143005`。改坏了把备份改名回 `SaveFile.txt` 即可还原。

5. **免责**：改本地存档可能违反游戏用户协议，理论上存在封号风险，自己掂量。联机时你的等级和金钱会显示在别人界面上。本工具仅供学习交流。

## 三、怎么用

### 基本流程

1. 顶部确认存档路径 → 点「读取存档」
2. 左侧选分类，或直接搜索框输关键词（按字段名或中文名过滤）
3. 改字段（改过的卡片会高亮，顶部「已改 N 项」实时计数）
4. 点「应用修改」→ 弹出确认框列出所有改动（原值 → 新值）→ 确认写盘

改动只在点「应用修改」并确认后才真正写入磁盘。中途点「还原全部」可放弃所有未写入的改动；单个字段右侧也有「还原」按钮。

### 一键预设

预设栏的四个按钮**只改内存中的值，不写盘**——执行后会弹窗说明改了哪些、遵循什么规则，你仍需点「应用修改」确认。这样能先看效果再决定。

| 预设 | 作用 | 安全规则 |
|---|---|---|
| 解锁全装备 + 全三阶 | 21 种可升级装备的一二三阶解锁全部打开，阶级拉到 3 | — |
| 金钱拉满 + 库存拉满 | 金钱设 999999999，装备库存提到上限（默认 99，可改） | **只升不降**：已高于上限的字段保持原值 |
| 设定等级 / 转生 | 输入目标等级与转生次数 | 见下方「关于等级」 |
| 全成就 / 挑战完成 | 成就计数补到目标值，挑战完成/领取位从 0 置 1 | **只升不降** + **不动 Progression** |

**为什么预设要「只升不降」**：实测存档里有些挑战用进度值表达完成，比如 `lighthouseKeeperCompleted = 50`（不是 1）。如果无脑把所有"已完成"字段置 1，反而会把它降级成"未完成"。所以预设只在"当前值 < 目标值"时才提高，绝不改小。Progression（各挑战进度）的目标值因挑战而异（有 50 也有 1），乱填可能破坏判定，预设一律不碰，需要时手动改。

## 四、关于等级（重要，与旧版不同）

旧 Python 版的说明写着"存档没有等级字段，等级靠经验值现算"，**这个结论已经过时了**。通过对身份卡渲染图和游戏日志的实证核对，当前版本是这样：

| 字段 | 真实含义 | 实证依据 |
|---|---|---|
| `NewLevel` | **身份卡上显示的等级** | 身份卡印 "V-075"，存档值正好 75 |
| `Prestige` | **转生次数**（等级前的罗马数字，V=5） | 存档值 5，游戏日志打印 `Prestige: 5` |
| `Experience` | **当前等级内的进度经验**，不是累计总经验 | 身份卡印 "177/4024"，存档值正好 177 |
| `Level` | 旧版遗留字段，当前版本不用于显示 | 对应日志里的 "Legacy Level" |
| `myTotalExp` | 用途未能确认 | 两个开源修改器都不读写它 |

所以**改等级直接写 `NewLevel` 即可**，不用再走经验换算公式。「设定等级」预设就是直接写 `NewLevel`（范围 1~9999）和 `Prestige`（范围 0~3999）。这个结论与 GitHub 上两个仍在维护的开源修改器（BitterG/Phasmophobia-Save-Editor、stth12/PhasmoEditor）一致。

`Experience` 作为普通字段也能改，但它是"本级进度"，改了只影响当前这一级的经验条，不影响等级数字。

## 六、复杂类型编辑器

存档是 Easy Save 3 写出的**非标准 JSON**（字典 key 是裸整数 `{11:166}`，外观字典甚至用对象当 key），无法用常规 JSON 解析器整体读取。本工具对每类复杂字段做了专用编辑器：

- **颜色**：RGBA 四分量 + 十六进制预览块
- **字典**：可编辑表格，支持增删行（地图游玩次数、鬼种统计）
- **列表**：可增删条目（玩家名单）
- **外观**：槽位 + guid + 材质选项表格
- **衣柜**：已拥有外观的 guid 列表，可增删
- **难度**：`LastDifficulty` 含内部引用 ID（`_ES3Ref`），改动可能在游戏内失效，故**默认只读展示**

> 外观的 guid 对应游戏内的具体服饰资源，但 guid→物品名的映射需要挖游戏资源，目前只能按 guid 编辑，暂不显示物品名。

**安全性保证**：所有复杂字段遵循"未修改就保留原文"——没动过的字段写回时是逐字节还原的，不会因为格式复刻的细微差异而改动存档结构。这一点经过 597 字段的往返测试验证。

## 七、写入保护机制

程序写盘前有三道闸，任一不过就不写，原存档不受影响：

1. **进程检测**：游戏在运行则拒绝写入
2. **加密回读自检**：`解密(加密(新内容)) == 新内容`，不通过则放弃写入
3. **时间戳备份 + 原子写**：先备份，再通过临时文件替换写入，避免写一半损坏

## 八、技术说明

- **技术栈**：.NET 9 WPF，纯 C#，**无任何 NuGet 依赖**（离线可构建）
- **加密**：AES-128-CBC + PBKDF2-HMAC-SHA1（salt = IV，100 轮，密码是 Easy Save 3 默认密码），用 .NET 内置 `System.Security.Cryptography` 实现，与旧 Python 版逻辑一致
- **等级公式**：不再使用旧版的 `100×(L-1)^1.73` 经验换算（已过时），改为直接写 `NewLevel`

## 九、「应用修改」点不动 / 无法写入

按这个顺序排查：

1. **按钮是灰的** —— 说明还没有任何改动，或存档没加载成功。先看状态栏：正常应显示「已加载 597 个字段：SaveFile.txt」。若显示「找不到存档文件」，点「浏览」手动选 `AppData\LocalLow\Kinetic Games\Phasmophobia\SaveFile.txt`。
2. **按钮能点，但弹窗说字段校验未通过** —— 弹窗会列出具体是哪个字段、错在哪（例如「金钱（PlayersMoney）：不能大于 999999999」）。改成合法值，或点「还原全部」放弃这些输入。红框标出的就是问题字段。
3. **弹窗说游戏正在运行** —— 必须完全退出恐鬼症（含 Steam 后台进程）再改，否则游戏退出时会用内存里的旧存档覆盖你的修改。
4. **提示没有写入权限** —— 存档目录被设为只读或被占用，可尝试以管理员身份运行。
5. **写入成功但进游戏没变化** —— 云存档回滚了。见下方「云同步」一节。

> 排查用的技术细节：`CanApply`（能否写入）与 `ApplyEnabled`（按钮是否可点）是**两个不同的属性**，故意不相等。
> 有字段校验失败时按钮仍保持可点，这样点开才能看到「哪些字段不合法、该怎么改」；
> 如果直接用 `CanApply` 置灰按钮，WPF 的 Click 不会触发，用户只会面对一个灰按钮，
> 完全不知道为什么点不动。这是本工具曾出过的真实 bug，测试里有专门的回归用例守着
> （`tests\E2ETests`，第 5、6 组）。

另外，非法输入（比如金钱填了超出上限的数字）**不会被静默忽略**：它既会拦住写入，
也仍然算作「已修改」，所以字段旁的「还原」和顶部「还原全部」都能正常把它清掉，
不会把界面锁死。

## 十、游戏更新后失效怎么办

如果游戏大版本更新后工具报错或改不动，通常是两种情况：

1. **密码/迭代次数变了**：作者终于改了 Easy Save 3 默认密码。需按旧版 README「怎么扒出来的」重新逆向，改 `Core\SaveCrypto.cs` 里的 `Password` 与 `Iterations`。
2. **存档格式变了**：字段类型或结构变化。重新解密存档枚举字段清单（可直接复用 `tests\CoreTests` 的字段枚举断言），对比差异后调整 `Schema\FieldCatalog.cs` 的分类规则或 `Complex\` 下的解析器。

改完务必重跑两个测试工程确认没写坏存档：

```bash
dotnet run --project tests\CoreTests\CoreTests.csproj    # 加解密 / 597 字段 / 往返一致
dotnet run --project tests\E2ETests\E2ETests.csproj      # 改动生效 / 未触碰字段逐字节不变 / 完整写入
```

两者都只在**副本**上操作，不会碰你的真实存档。
